# PingMe 自动化任务（签到 / 看视频奖励 已拆分）

订阅地址：`https://raw.githubusercontent.com/a13609y/1/refs/heads/main/egern/PingMe.yaml`

## 三个脚本

| 脚本 | 触发 | 作用 |
| --- | --- | --- |
| `pingme-capture.js` | `http_request` 抓 `api.pingmeapp.net/app/queryBalanceAndBonus` | 把账号参数存进 `pingme_accounts_v1`（多账号，同一账号重复抓只更新） |
| `pingme-sign.js` | `schedule`（签到 cron） | 只做签到 |
| `pingme-video.js` | `schedule`（看视频 cron） | 只做看视频得奖励（每次循环 5 个视频） |

两个任务彻底分开：cron 各一个、开关各一个、失败互不影响。

## 模块设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 禁用账号抓取 | 关 | 抓包装好后正常用不要再开 |
| 关闭自动签到 | 关 | 打开 = 只跑看视频奖励 |
| 关闭看视频奖励 | 关 | 打开 = 只跑签到 |
| 签到 cron | `30 4-23 * * *` | 见下方「为什么签到是每小时一次」 |
| 签到超时 | 300 秒 | |
| 看视频 cron | `20 20 * * *` | 每天 20:20 跑一次 |
| 看视频超时 | 300 秒 | |

## 签到逻辑（与 `pingmeqd.js` 一致）

- **滚动签到小时**：锚点 `START_DATE = 2026-07-14` 当天固定 4:30，之后每天 +1 小时，到 23:30 后绕回 4:30（20 天一轮）。三个常量 `BASE_HOUR / FIXED_MINUTE / START_DATE` 在脚本顶部。
- **当天追赶制**：只要当前时间已过今天的目标时刻、且今天还没签成功，任何一次整点触发都会补签，一直追到 23:30。设备整天没被唤醒才会漏签。
- **标记时机**：`checkIn` 真正拿到服务器响应后才记「今天已处理」；网络层失败（超时/断网/HTTP 异常）不标记，下一个整点自动重试。
- 每个账号每天只真正签到一次（按账号 id 分别记录 `pingme_sign_last_run_v1`）。

### 为什么签到 cron 是每小时一次而不是每天一次？

脚本的「滚动 + 追赶」就是靠每小时一次的触发来兜住漏签。`30 4-23 * * *` 看起来是 20 次/天，但内部有闸门，
每次只有一个账号在「过了目标时刻且今天没签」时才真正发请求，**结果就是每天签到一次**。

如果你更想要「每天固定一个时间跑一次」，可以把签到 cron 改成例如 `35 23 * * *`（必须晚于当天最晚目标时刻 23:30），
同样能正常工作，代价是那一分钟设备没醒就当天漏签。

## 看视频逻辑（与旧版一致）

- 每账号：查余额 → `videoBonus` 循环 `MAX_VIDEO = 5` 次（首次 1.5 秒后开始，之后间隔 `VIDEO_DELAY = 8000` ms，
  每次都用新生成的伪造 `uniquedeviceid`）→ 再查一次余额。
- 中途返回业务错误（如「今日视频奖励已达上限」）立即停止当次循环。
- 账号返回「已被注销」会自动从仓库移除。

## 抓包 / 使用顺序

1. 装模块 → 打开 MITM（`api.pingmeapp.net`）→ 打开 PingMe App 进一次「余额/奖励」页面触发抓包，收到「✅ 新账号已入库」即可。
2. 之后不用再打开 App，定时任务会在 Egern 运行期间自动跑（App 被杀时错过的那次改天补跑一次）。

## 兼容说明

- 账号仓库键沿用 `pingme_accounts_v1`，**旧版抓到过的账号不用重新抓**。
- 也兼容单账号的 `pingme_capture_v3` 键（旧签到脚本时代抓的），仓库为空时自动回退读取。
- `script_url` 在 Egern 有约 24 小时缓存，改了脚本要「删模块重新导入」才会拿到新代码。
